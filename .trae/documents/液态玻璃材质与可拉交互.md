# 玻璃材质三档 + 可拉液态玻璃

## Context（为什么做）

现在的外观系统只有一根 0–100 的「通透度」滑杆（`ui.glassLevel` → CSS 变量 `--g`），用户调不出"材质"的区别：模糊强度是被 `--g` 反推出来的，越透越清晰，所以做不出"半透明但很糊还带颗粒"的亚克力。早先那套字符串档位（`ui.glass`）已在 `config.js` 的 `sanitize()` 里被删掉。

用户要两件事：

1. **三个材质档：透明 / 亚克力 / 不透明**。定位是**快捷预设**——点一下把材质参数和滑杆值一起跳到该档代表值，之后滑杆仍能自由微调（不取代滑杆）。
2. **可拉的液态玻璃**，像 iOS 26 那样，两件事叠加、作用于**所有玻璃元素**（卡片/面板/顶栏/侧栏/弹窗）：
   - 高光跟随指针流动（划过或按住时，玻璃表面的反光跟着鼠标走）；
   - 按住拖动时玻璃像果冻一样被拉长挤扁，松手橡皮筋回弹。
   - 明确**不做**：水银融合（gooey / SVG feDisplacementMap）、拖拽改尺寸。

亚克力的质感定义：半透明 + 强模糊 + 细颗粒噪点（Windows 亚克力味道），不能糊成奶白、文字要清楚。

约束：不破坏现有四个外观模式（深色/浅色/OLED/跟随系统）、自定义背景（图片/动图/视频）、正常点击与滚动、以及 OS 文件拖拽导入。

## 核心设计决策

**材质与通透度解耦**：`glassMaterial` 只表达"材质"（模糊倍率 + 颗粒噪点），`glassLevel` 只表达"通透度"。所以新增一个变量 `--glass-blur-k`（模糊倍率）而不是直接覆盖 `--glass-blur`，滑杆才能继续连续微调模糊。点档位时同时写这两个键；拖滑杆只写 `glassLevel`，档位按钮的状态由 `glassLevel` 是否等于某档代表值**派生**（不用定时器、不留第二份真源）。

**变形挂在元素自身**，不加外壳层（加壳要改 50+ 处渲染模板）。已核实：所有目标类都是 `position: relative`，`.topbar`/`.sidenav`/`.modal` 都**不是** fixed/sticky，全项目的 `position: fixed` 只有 `.bg-layer`/`.modal-mask`/`.toast`/`.global-loading`，都不是玻璃元素的后代 → 给玻璃加 `transform` 不会改写任何 fixed 后代的包含块。

**顶栏只给高光、不给可拉**：`.topbar` 是 `-webkit-app-region: drag` 的系统拖拽区，且"拖顶栏 = 拖窗口"是既有且更重要的交互，不能被 6px 阈值抢走。

**`.modal` 需要补 `position: relative`**：它现在是 `static`，直接给 `.modal::after` 加 `position:absolute` 会以 `.modal-mask`（fixed, inset:0）为包含块铺满整屏。

**高光层挂哪个伪元素**（已核实占用情况）：`.glass/.panel/.card/.sv-card` 的 `::before` 已被"顶部 1px 高光条"占用（最终生效规则在 `styles.css` L3032），`::after` 在这些类上全空 → 高光用 `::after`；`.topbar::after` 已被占用（L2886）、`.topbar::before` 与 `.sidenav::before` 空闲 → 顶栏/侧栏用 `::before`。

**高光层 z-index:-1 依赖"元素有 backdrop-filter"**：`backdrop-filter` 会创建层叠上下文，负 z-index 后代才会落在"元素背景之上、内容之下"。所以「不透明」档把模糊倍率设为 0 时**仍保留 `backdrop-filter: blur(0px)` 属性**（`blur(0px)` 不是 `none`，照样建层叠上下文）。

**亚克力噪点用元素自身 `background-image` 的第二层**，不用伪元素、不复用 `.bg-grid`：天然位于"backdrop 结果之上、内容之下"，不遮文字、不抢伪元素、零布局影响，8px 平铺靠 GPU，而 `.bg-grid` 在 `.bg-layer` 里会被玻璃自身 28px 模糊糊掉。

**事件用 `document` 上只绑一次的委托**：卡片是每次 `renderPage()` 重建的，项目现有交互全是元素上直接 `onclick`，没有委托。委托不随页面重建失效。只监听 `pointermove`/`pointerdown`/`pointerup`/`pointercancel`（不用 `pointerover`/`pointerleave`，后者不冒泡），用 `closest()` 找玻璃根、再 `closest()` 排除表判断"命中控件就不抢"。

**果冻数学做成纯函数放新文件**：`src/renderer/glass-motion.js`，UMD 包裹（`module.exports` + `window.GlassMotion`），文件内不出现 `window`/`document`，这样 `smoke.js` 能直接 `require` 它断言算法，不用真跑鼠标。

## 三档参数表

| 项 | 透明 | 亚克力 | 不透明 |
|---|---|---|---|
| `ui.glassLevel`（滑杆值） | 88 | 45 | 4 |
| `--g` | 0.88 | 0.45 | 0.04 |
| `--glass-blur-k`（新增） | 1 | 1.7 | 0 |
| 实际 `--glass-blur` | 3.6px | 28.05px | 0px |
| 颗粒噪点 | 无 | 有（0.12 alpha 黑白噪点，8px tile） | 无 |
| `body[data-transparent]` | `"1"`（88≥70，复用既有轮廓加强规则） | `"0"` | `"0"` |
| 观感 | 只剩一层淡玻璃，桌面/背景图基本原样透出 | 半透明 + 强模糊 + 细颗粒 | 面板近实心，文字最锐，且不模糊 = 省 GPU |

老配置迁移：`ui.glassMaterial` 默认 `'custom'` → `--glass-blur-k = 1`、无噪点、`g` 仍是 55，**与今天像素级一致**，不需要额外的迁移逻辑。

`light` / `OLED` 块（`styles.css` L3277-3306 / L3315-3445）只重定义 `--bg-*`/`--text*`/`--border*`/`--glass-shadow`/`--glass-sheen`，**不碰** `--g`/`--glass-blur`/`--glass-sat`，所以我们新增的 `--glass-blur-k`（JS 内联在 body）与 `--glass-noise`（CSS）不会被覆盖错。要按模式调的只有高光强度 `--live-a`（深色 .16 / 浅色 .45 / OLED .12，属 CSS 变量，可被 light/OLED 规则覆盖）。

## 改动清单

### 1. 新建 `src/renderer/glass-motion.js`（纯函数，UMD）

导出四项：

- `LIMITS`：`{ SPAN_FRAC: 0.04, PULL_FRAC: 0.32, STRETCH: 0.03, SQUASH: 0.66, TILT: 0.8 }` —— 所有上限集中在这里，smoke 直接断言。
- `MATERIALS` + `PRESETS`：三档参数表 + `custom`（`g: null, blurK: 1, grain: false`）。
- `normalizeMaterial(id)`：非法值回落 `'custom'`。
- `materialForLevel(level)`：`level` 等于某档代表值就返回该档 id，否则 `null`（"自定义"是**派生**的）。
- `jellyTransform({ dx, dy, w, h, velocity })` → `{ tx, ty, a, b, tilt, dir, transform }`。

果冻公式：

```
span = hypot(w, h)                      // 对角线做尺度基准，宽卡/窄栏通用
dist = hypot(dx, dy)
t    = min(1, dist / (span * PULL_FRAC))   // 拖到对角线 32% 即满强度
s    = t*t*(3-2t)                       // smoothstep：起步柔、后段稳
dir  = atan2(dy, dx)
tx   = ux * span * SPAN_FRAC * s        // 位移上限 = 对角线 4%
ty   = uy * span * SPAN_FRAC * s
a    = 1 + STRETCH * s                  // 沿拖拽方向拉长 ≤ +3%
b    = 1 - STRETCH * SQUASH * s         // 垂直方向压扁 ≤ -2%
tilt = clamp( (velocity ? (vx*uy - vy*ux)/900 : 0)
              + TILT * 0.35 * s * sin(2*dir), -TILT, +TILT )   // 度
transform = `translate3d(${tx}px, ${ty}px, 0)`
          + ` rotate(${deg(dir)+tilt}deg) scale(${a}, ${b}) rotate(${-deg(dir)}deg)`
```

`rotate(dir+tilt)·scale(a,b)·rotate(-dir)` 是"沿 dir 方向拉伸、垂直方向压扁，再整体歪 tilt 度"的精确仿射写法，不需要 `matrix()`，也不引入 `perspective()`（位移/角度这么小，透视无视觉收益，只会多一套栅格化路径）。

文字不会变形的硬保证：横向 ≤3%、纵向 ≤2%、旋转 ≤0.8°、平移不改字形 —— 全部由 `LIMITS` 卡住。
退化输入（`w`/`h ≤ 0`、非有限数、`dist < 0.01`）一律返回恒等变换，永不抛。输出数值统一保留 3 位小数，避免 `transform` 串出现长浮点或 `NaN`。

### 7. `src/renderer/app.js` —— 可拉交互委托 `bindLiquidGlass()`

在 `bindGlobalEvents()`（L6001）里挂一行。要点：

- `JELLY_ROOT`：`.glass,.panel,.panel-strong,.glass-strong,.card,.cat-bar,.stat-card,.sv-card,.dl-row,.skin-cell,.inst-card,.theme-card,.widget,.quick-card,.acc-card,.modal,.sidenav`（**不含 `.topbar`**）。
- `JELLY_EXCLUDE`：`button,a,input,select,textarea,label,[contenteditable="true"],.ui-opt,.ui-check,.accent-dot,.topbar-drag,[data-no-jelly]`，另外**向上遍历到玻璃根之前只要遇到带 `onclick` 的元素也算控件**（覆盖 `.accent-dot` 这类 div + onclick 的写法）。
- `pointermove` 只记坐标（`{ passive: true }`），写入全放 `requestAnimationFrame`，一帧只写 1 个元素（`hoverEl` 或 `dragEl` 二选一）、最多 4 个属性（`--mx`/`--my` + 拖动时的 `transform`）。
- `pointerdown` 不 `preventDefault`、不 `setPointerCapture`；**位移 ≥6px 才升级为拖动**（<6px 视作点击，绝不抢），升级时才给元素加 `.jelly-drag` 并 `try { el.setPointerCapture(id) } catch {}`（合成事件会抛）。升级后挂一次捕获阶段 `click` 抑制（`{ capture:true, once:true }` + `setTimeout` 兜底移除），保证"拖完不乱触发卡片原本的 onclick"。
- 收手：`pointerup` → 清空内联 `transform` + 加 `.jelly-release`（460ms 后移除，也是兜底清理）；`pointercancel`、`window.blur`（指针在窗外松开）、拖动中 `scroll`（避免基准错位）、以及 `renderPage()` 开头各调一次 `finish(false)`（DOM 被重建时收手）。写入前判 `el.isConnected`。
- `will-change` 只在拖动期间加、结束撤掉。
- `prefers-reduced-motion: reduce` 时跳过硬变形（不加 `.jelly-drag`/`.jelly-release`），高光保留。
- 与 OS 文件拖拽导入不冲突（系统接管期间不产生 pointer 事件），再加保险：`dragenter` 命中 Files 时调 `finish(false)`。

### 8. `src/renderer/browser.js`（可选，1 行）

内置浏览器**只同步材质标识**（`applyLook()` 里多写一个 `body[data-material]`），**不做可拉交互**：`browser.css` 里没有任何 `backdrop-filter`/`--g` 消费点，浏览器窗口头部本身是系统拖拽区、中间是 `<webview>`，抢指针风险换不来收益。现状 `applyLook()` 也只在开窗时跑一次。

## 风险与降级

| 风险 | 兜底 |
|---|---|
| 拖大卡片时掉帧（每帧重取 28px 模糊 backdrop） | 优先轻的：①`.jelly-drag` 内把该元素的 `--glass-blur-k` 降到 0.5–0.6；②该元素拖动中 `backdrop-filter: none` 但必须同步把高光层 `z-index` 改成 0（否则高光会沉到元素背景之后消失）；③`LIMITS.SPAN_FRAC` 减半 |
| 顶栏空白处收不到指针事件（系统拖拽区） | 属预期行为，不算 Bug；顶栏高光只在 no-drag 子控件（搜索框/右侧按钮区）上出现。不做额外补偿 |
| 合成 `PointerEvent` 下 `setPointerCapture` 抛异常 | `try/catch` 是硬要求；收手依赖 `document` 上的 `pointerup/pointercancel` + `window.blur` |
| 拖动中内联 `transform` 吃掉 `.card:hover` 的 2px 上浮 | 拖动期间视觉可接受，松手清空即恢复（`.card` 本来就有 transform 过渡） |
| 亚克力噪点过脏（0.12） | 调参集中在一处（SVG 里 `rect opacity`），改 0.08；light 模式下另可整条 `--glass-noise: none` |
| 少数玻璃类带 `overflow: hidden`，`inset:-1px` 的高光被裁 1px | 视觉无损，接受 |
| 运行期写入非法 `glassMaterial`（浅合并 + sanitize 不立即跑） | 渲染层 `normalizeMaterial()` 兜底，重启后 `sanitize()` 纠正 |
| 纯模块被主进程 require 时误用 DOM API | 模块内禁写 `window`/`document`；H-17 ①–⑦ 就是它的冒烟门槛 |

**待实测确认（实现后第一件事）**：Chromium 在 ≤3% scale / ≤0.8° rotate / ≤18px translate 下，`backdrop-filter` 的采样是否会可见错位或边缘裁切。验证方法：临时把 `LIMITS` 放大 10 倍对比同一元素的边缘与模糊位置，确认"只有大变形才失真"，然后复原。

## 验证

### H-17 冒烟（`e:\CM\smoke.js`）

顶部加 `require('./src/renderer/glass-motion.js')`，末尾 `app.exit(... || h17Bad ? 1 : 0)` 追加 `h17Bad`。断言 11 项：

1. **三档参数表**：`PRESETS.length === 3`、`g` 都在 0–100、`acrylic.g === 45 && blurK > 1 && grain === true`、`transparent.blurK === 1`、`solid.blurK === 0`，且与 `data-transparent` 判据对齐（`transparent.g >= 70`，另两档 `< 70`）。
2. **档位派生**：`materialForLevel` 对 45/88/4 命中对应档，对 55/44 返回 `null`。
3. **非法配置回落**：`config.sanitize({ ui: { glassMaterial: '乱填' } })` → `'custom'`，且旧键 `ui.glass` 仍被清掉（需先导出 `sanitize`）。
4. **静止与退化输入**：`dx=0` 时 `a=b=1`、`tx=ty=0`、`tilt=0`、无 `NaN`；`w/h=0` 与空参数不抛且返回恒等。
5. **变形上限**：`dx=5000, dy=-5000` 时 `a <= 1.0301`、`b >= 0.9799`、`|tilt| <= 0.8`、位移 `<= span*0.04`。
